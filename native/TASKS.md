Flutter API maps to its Compose equivalent (`showModalBottomSheet` -> `ModalBottomSheet`,
`DropdownMenu` -> `ExposedDropdownMenuBox`, `ScrollController` -> `NestedScrollConnection`).

## Phase 23 - Blur, not frosted: solid sheets over a page that blurs in step with them
- [x] On a phone the blur arrived after the sheet had opened. It was the window manager's blur behind the sheet's window (`FLAG_BLUR_BEHIND` + `blurBehindRadius`): every change is a request to the system server, applied a frame or more later, so the ramp trailed the sheet. Now the app blurs the page itself: the root draws the page through a `RenderEffect` blur whose radius is read every frame from where the sheet actually is (`AppOverlays.backdropBlur`, fed by `Modifier.blursBackdrop` on the sheet's content). It rises as the sheet slides up, follows a drag, falls as the sheet goes down, and lands with it. Measured in a render test frame by frame: the page is partly blurred in the same frame the sheet is partway up, never sharp under a moving sheet
- [x] Blur, not frosted glass: sheets and dialogs are solid (`surfaceContainerLow` / `surfaceContainerHigh`) - no translucency, grain, milky veil or edge light; the Material scrim above the blurred page. A tall sheet resting half-open blurs the page fully (full at 40% of the window). Centred dialogs (date, time, month, date range) fade the same page blur in over 200ms; a sheet removed all at once (the app locking) eases it out over 200ms instead of snapping
- [x] Same rule as before for where it applies: the "Background blur" setting (was "Frosted glass"), Android 12+, and the system's blur on (battery saver or the developer option off -> the page stays sharp and the floating bars are solid)
- [x] Removed: window-manager blur, `FROSTED_SHEET_ALPHA`, grain, top-edge light, frosted tokens (surface / scrim / grain / border / edge alpha). `AppFrostedTokens` is now blur 40dp, bar glass 20dp, corner 28dp
